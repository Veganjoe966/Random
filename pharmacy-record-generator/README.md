# 90-Day Pharmacy Dispensing Record Generator

> **IMPORTANT DISCLAIMER**
> All data generated by this application is entirely **SIMULATED** and is intended exclusively for:
> - Compliance simulation and testing
> - Internal audit preparation
> - Staff training and education
>
> Generated records have **no legal, regulatory, or pharmaceutical validity** and must never be used in real pharmacy operations, submitted to any regulatory body, or represented as actual patient data.

---

## Overview

A production-grade Streamlit application that generates realistic 90-day pharmacy dispensing records across controlled and non-controlled medications. Built for healthcare compliance teams, pharmacy audit professionals, and training departments.

### Key Capabilities

| Feature | Detail |
|---|---|
| **Drug Coverage** | CII–CV controlled substances + 25+ non-controlled maintenance/acute meds |
| **NDC Lookup** | Live FDA OpenFDA API with local caching and fallback |
| **DEA Validation** | Full checksum algorithm validation |
| **NPI Validation** | Luhn algorithm verification |
| **Prescriber Upload** | CSV / Excel with fuzzy column detection |
| **Export** | Excel (.xlsx with Summary sheet) + CSV |
| **Volume** | 100–5,000 records per run |

## Setup Instructions

### Prerequisites

- Python 3.9 or higher
- pip

### Installation

```bash
# 1. Clone or download the project
cd pharmacy-record-generator

# 2. Create a virtual environment (recommended)
python -m venv .venv
source .venv/bin/activate        # macOS / Linux
.venv\Scripts\activate           # Windows

# 3. Install dependencies
pip install -r requirements.txt

# 4. Launch the application
streamlit run app.py
```

The app will open automatically in your browser at `http://localhost:8501`.

## Usage Guide

### Step 1 — Pharmacy Configuration (Sidebar)

Fill in the pharmacy details in the left sidebar:
- **Pharmacy Name**, **NPI**, **DEA Number** (validated in real-time)
- **Address**, **City**, **State**, **ZIP**
- **Period End Date** — the app auto-calculates the 90-day rolling window
- **Target Record Count** — 100 to 5,000 records

### Step 2 — Upload Prescriber List (Optional)

Navigate to the **"Step 1 — Upload Prescriber List"** tab.

Upload a CSV or Excel file containing prescriber information. Column headers are auto-detected using fuzzy matching — the file does not need exact column names.

See `sample_output/sample_dea_prescribers.csv` for a reference format.

**If no file is uploaded**, 60 simulated prescribers are auto-generated with realistic specialties and valid DEA numbers.

### Step 3 — Generate Records

Click the **"Generate Records"** button. The engine will:

1. Pre-fetch NDC data from the FDA OpenFDA API (cached after first run)
2. Generate patient pool (~35–50% of target = unique patients)
3. Produce controlled substance records (CII–CV, ~28% of total)
4. Produce non-controlled records (~72% of total)
5. Apply refill logic (30-day cycles, CII = no refills)
6. Assign sequential RX numbers with realistic gaps

### Step 4 — Results & Export

Review summary metrics, top drug charts, and filtered record previews.

Download:
- **Excel (.xlsx)** — 3 sheets: Dispensing Records, Summary, Validation Report
- **CSV** — flat file with disclaimer header

## DEA Validation Algorithm

```
DEA format: [Registrant Type][Last Name Initial][7 digits]
Example:    AB1234563

Digits: d1=1, d2=2, d3=3, d4=4, d5=5, d6=6, d7=3
odd_sum  = d1 + d3 + d5 = 1 + 3 + 5 = 9
even_sum = d2 + d4 + d6 = 2 + 4 + 6 = 12
checksum = (odd_sum + 2 * even_sum) % 10 = (9 + 24) % 10 = 3 ✓ (matches d7)
```

## NDC API Integration

Uses the **FDA OpenFDA Drug NDC endpoint**:
```
GET https://api.fda.gov/drug/ndc.json?search=generic_name:"<drug>"&limit=5
```

- Results are cached locally to `cache/ndc_cache.json`
- 11-digit normalization handles all three FDA NDC formats (4-4-2, 5-3-2, 5-4-1)
- API failures fall back to a deterministic hash-based placeholder NDC
- All API errors are logged to `logs/generator.log`
